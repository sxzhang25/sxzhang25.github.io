Method

{% capture caption %}The four stages of our verification pipeline. 1. Dataset generation. We first curate a dataset of training examples from a generator or an existing dataset. 2. Dev set labeling. The user then labels a small random subset (about 10) of these examples as positive or negative, possibly providing notes alongside each label, e.g. “the piano is not in the corner.” 3. Weak verifier generation. We provide an LLM with the user prompt, the labeled dev set examples, and documentation of our DSL and query it to generate a set of weak verifiers. 4. Weak verifier aggregation. We run all the weak verifiers on our entire training dataset and aggregate them into a single strong verifier.{% endcapture %} {% include publication-figure.html src="/publications/imgs/layout-weak-verifiers-pipeline.png" alt="The four stages of our verification pipeline" caption=caption %}

Our verification pipeline takes a user's task description of the desired layout as input and outputs a strong verifier that evaluates whether a generated layout matches the prompt. Rather than directly using an LLM as a judge, our approach is to use the LLM to generate many task-specific verifier programs. To help the LLM write programs with complex spatial logic, we design a verification domain-specific language (DSL) that defines low-level spatial layout queries. To make weak learning work in our setting, we encourage our LLM-based weak verifier generation to produce diverse verifier programs, and then filter for a subset of higher-quality weak programmatic verifiers before aggregating their responses.

Verification Results

Our experiments over three different layout domains (3D rooms, 2D posters and 3D objects) find support for three main claims: (1) Using our programmatic weak verifiers in combination with any of the aggregation techniques outperforms directly using LLMs as judges by up to 6.5x in F1-score; (2) Weaver aggregation generally outperforms the other aggregation methods with as few as 10 labeled layout examples; (3) Using our strong verifiers in verifier-guided layout generation with Detailed feedback improves a base layout generator from 37.2% to 77.3% (a 40.1 point improvement) according to human evaluation.

Verifier-Guided Layout Generation

In addition to verification, we also use our strong verifiers for verifier-guided layout generation—a process that automates the iterative generate-then-verify loop. To explore how the information within the verifier programs can help this process, we investigate two different forms of verifier feedback in this loop: Binary feedback, which simply uses the True/False verification decisions; and Detailed feedback, which uses natural language messages explaining the decisions. Since our feedback messages come from many different weak verifiers of varying quality and logic, we contextualize the individual feedback messages with a reliability score defined using the learned aggregation weights.
